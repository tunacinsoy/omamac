# Font size Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `omamac font-size` picks Ghostty's font size (10–20 or Default) from a picker with hints or an argument, and every later write of omamac's Ghostty file keeps it.

**Architecture:** The size lives in its own state file. `ghostty_render` (lib/ghostty.sh), which install, update and theme already call, appends `font-size = N` when a valid size is saved. A new lib/fontsize.sh holds the command: pick or parse, save, rewrite only omamac's Ghostty file, send Ghostty the reload signal, print one line.

**Tech Stack:** bash 5, gum 2.0.2 (`choose --selected` matches the *label*, checked on the host), bats, the Tart VM loop.

**Spec:** `docs/superpowers/specs/2026-11-27-font-size-design.md`

## Global Constraints

- Sizes: 10 to 20, and `default`. Picker labels, in this order: `10`, `11  more on screen`, `12`, `13`, `14  laptop`, `15`, `16  external monitor`, `17`, `18  monitor further away`, `19`, `20  presenting or sharing your screen`, `Default`. Values are `10`…`20` and `default`.
- Picker header: `Which size?`. The cursor starts on the current size's label (`Default` when none is saved).
- Output: the terminal look prints one row, `ui_row ok "Font size" "<16|Default>"`; plain output prints `ui_ok "Font size: <16|Default>"`. Nothing else: no Ghostty, file or override lines.
- Bad size: `ui_fail "Font sizes are 10 to 20, or default."`, exit 2. More than one argument: usage on stderr, exit 2.
- State file: `$OMAMAC_STATE_DIR/font-size`, one line holding the number. `default` deletes it. Read as data, never sourced.
- Not a question in lib/questions.sh; first run, update and doctor never ask about it or mention it.
- Menu label: `Change the font size:font-size`, right after `Switch the theme:theme`.
- The user's own Ghostty config is never written.

## Review Focus

- A hand-edited state file (`abc`, `25`, `$(rm -rf ~)`, empty, two lines): no font line is written and nothing runs; `omamac font-size` still works and overwrites it. → Task 1 test "render ignores a bad saved size".
- `omamac font-size 16` with no choices file (omamac never set up): stops with the existing "doesn't know your answers" message, like `omamac theme`. → Task 2 test "font-size with no saved answers stops".
- `omamac update` / `omamac theme nord` after a size is picked keeps `font-size = 16`. → Task 1 test "theme switch keeps the size".
- Esc / Ctrl-C at the picker changes nothing (no state file, Ghostty file unchanged). → Task 2 test "Esc at the picker changes nothing".
- `omamac font-size 016`, `16.5`, ` 16`: rejected, exit 2. → Task 2 test "font-size rejects near-numbers".

  - `"Esc at the picker changes nothing"`: `gum_answers "exit 1"`; status 130; no state file; `ghostty.conf` mtime unchanged (`stamp`-style).
  - `"font-size never touches the user's Ghostty config"`: user file `~/.config/ghostty/config` with `font-size = 14` stays byte-for-byte.
